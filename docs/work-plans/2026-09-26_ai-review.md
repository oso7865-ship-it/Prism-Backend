# 수동 DeepSeek 코드 리뷰 작업 계약

## 설계 및 범위

사용자의 1~6 단계 전체 구현 지시를 근거로 설계 후 구현한다. backend/frontend dev, architecture main. 정적 분석과 AI 실행을 분리하며 GitHub 댓글·자동 실행·코드 적용은 제외한다.

1. 완료된 정적 분석의 workspace/repository/connection generation/base/head에 리뷰를 귀속한다.
2. 초기 버전은 OWNER만 매 요청의 외부 전송 안내를 확인하고 요청한다. 멤버는 같은 팀 결과 조회 가능. OWNER/설치 권한은 접수, 외부 전송 직전, 완료 저장 시 재확인한다.
3. 전송 모드 BOUNDED_CODE_V1: 최대 8개 지원 언어 파일, 파일당 patch 8KiB, 전체 JSON 입력 24KiB. HEAD 변경 줄/주변 줄만 제공하고 삭제 줄·전체 파일·PR 본문·사용자 리뷰는 제외한다. 외부에는 파일 경로 대신 f1… 식별자를 보낸다. 비밀 패턴 포함 파일, 비밀 관련 정적 Finding, 제외 경로는 전송하지 않는다. 자동 탐지가 모든 비밀을 보장하지 않으므로 동의 문구에 기밀 코드 전송 한계를 명시한다.
4. LangChain ChatDeepSeek, JSON mode + Pydantic strict output. 요약/발견/근거/제안/한계. 입력 파일 ID와 제공된 HEAD 줄 밖 참조는 거부. AI 결과를 정적 Finding과 혼합하지 않음. HTML/Markdown 실행 없이 텍스트 렌더링.
5. 호출 1회, 자동 재시도 0, 출력 2000 tokens, 60초 timeout. Workspace당 UTC 일 5회 접수(실패/불확정도 소비), 동시 1개. 동일 analysis/model/prompt/policy는 기존 결과 재사용, 명시적 재실행만 새 generation. 금액 확정치 대신 토큰·호출 횟수와 과금 불확정 표시.
6. review_runs 한 테이블: UUID PK, 논리 관계(FK 없음), execution_key unique, 상태/시간/usage/check 제약. 결과 JSON은 검증 후만 저장. 원문 소스·diff·prompt·응답 원문·키는 저장하지 않음. 별도 FindingExplanation 테이블은 초기 JSON 결과로 대체하며 아키텍처에 기록.
7. 영속 EXPLAIN_FINDINGS Job 재사용. 외부 요청 이전에 호출 시도 표시를 커밋. 만료 lease는 재호출 없이 FAILED로 종결해 중복 과금 위험 축소. 취소/권한 철회 후 결과 저장 차단. 이미 전송된 요청은 되돌릴 수 없음.
8. DB 적용 전 pg_dump를 Git 제외 로컬 위치에 백업. additive migration만 upgrade. 실패 시 신규 runner OFF 및 이전 코드 복원; 개발 DB downgrade/기존 데이터 삭제는 하지 않음.
