## 설계

### 1. AI 출력 근거 계약

각 issue에 evidence_lines(같은 파일의 제공 줄 1~8개), trigger(발생 조건), consequence(관찰 결과), assumptions(미확인 전제 최대3개)를 요구한다. evidence_lines에는 대표 line과 변경 줄이 포함되어야 한다. 중복·허위 줄, SUPPORTED인데 미확인 전제가 있는 결과, NEEDS_CONTEXT인데 전제가 없는 결과를 거부한다. ERROR의 기존 SUPPORTED 제한을 유지한다. 순수한 미제공 문맥은 limitations에만 둔다.

이것은 의미를 증명하는 검증기가 아니다. 모델이 가정을 누락하거나 허위 설명을 붙일 가능성을 평가에서 별도 검수한다. 서버는 이슈를 조용히 삭제/강등하지 않는다. 과거 결과는 수정하지 않으며 UI 신규 필드는 optional이다. 원문 소스 인용을 새로 저장하지 않고 줄 번호와 짧은 설명만 저장한다. 기존 버전 hash가 schema 변경을 반영한다.

### 2. Windows

새 프로세스에서 npggNT64.des 로드 여부를 테스트 전후 관측한다. 별도 prism_test DB의 기존 전체 테스트를 실행하고 exit code와 native 진단 여부를 기록한다. 모듈이 로드된 경우 깨끗한 세션 검증으로 부르지 않는다. 진단이 없더라도 전체 환경의 영구 해결은 주장하지 않는다.

### 3. 정적 규칙

static-1.1.0에 COM-003, PY-004/005/008, JS-005/006을 추가해 29개를 활성화한다. 중첩은 조건/반복 구문만 세며 함수 경계에서 초기화, else-if 연쇄는 같은 깊이로 계산한다. 내장 호출은 파일 내 이름의 다른 사용/바인딩·동적 이름 변경 가능성을 보수적으로 검사하고 불확실하면 NOT_EVALUATED로 표시한다. PY-003의 빈 except와 PY-008을 중복 보고하지 않는다. 기본 OFF 설정 규칙·전역 타입 해석 등 나머지 9개는 후속이다.
