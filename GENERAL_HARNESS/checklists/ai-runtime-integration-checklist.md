## 2. 판정과 증거

모든 적용 항목에는 버전·환경·예상/관측 결과·증거 위치를 남긴다. 설계 단계는 계약 검토 결과로 한정하며 실제 실행 PASS로 표시하지 않는다. 해당 없는 항목은 사유 있는 N/A만 허용한다. 미확인은 결과 칸을 비우고 이유·담당자·다음 확인을 기록한다.

- PASS: 적용 항목이 모두 확인됐고 검수 범위와 일치하는 근거가 있다.
- WARN: 확정 위반은 없지만 일부 확인이 남았다. 책임 경계·계약 누락은 구조 WARN, 인증·민감정보 불명확은 위험 WARN으로 분류하여 GateGuard를 따른다.
- FAIL: 적용 필수 항목 위반, 인증/권한 우회, 검증되지 않은 응답의 성공 처리, 또는 실행 전제 조건 미비로 건너뛴 테스트를 통과로 간주함. 실제 실행 FAIL은 문서 검토 PASS로 덮지 않는다.

계약 테스트·실제 통합 테스트의 실행 전제 조건 미비는 `skills/verification-loop/SKILL.md`의 FAIL 규칙을 따른다. 구현되지 않은 설계 단계에 실행을 꾸며 넣지는 않는다. Gate 선택과 최종 판정은 `08.QUALITY_GATE.md §7-2`가 소유한다. Checklist PASS로 다른 Gate의 WARN/FAIL을 낮추지 않는다. 인계는 [AI Runtime Handoff](../AI_RUNTIME_HANDOFF_TEMPLATE.md)를 사용한다.
