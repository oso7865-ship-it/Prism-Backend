## 2. FAIL 기준

- PK 없는 핵심 테이블
- 관계는 있는데 FK/관계 설명 없음
- 필수 컬럼에 필수값(NOT NULL) 기준이 없음
- 중복 방지가 필요한 컬럼에 UNIQUE 기준이 없음
- 결제/주문 상태값 기준 없음
- 허용 상태값은 있는데 전이(어떤 상태에서 어떤 상태로 갈 수 있는지) 기준이 없음
- Soft/Hard Delete 중 어느 것을 쓸지 선택되지 않음
- `created_at`/`updated_at`/`deleted_at` 같은 시간 컬럼 기준이 아예 없음
- 금액 컬럼 의미가 불명확함
- 수량 컬럼 타입·음수 허용 여부가 불명확함

## 결과 요약

> 이 표는 **이 Checklist 자체의 판정**이다. 산출물 전체의 최종 판정은 `08.QUALITY_GATE.md §7-2`의 전역 공식(`maxSeverity(Verification, 적용 Gate 전부, 적용 Checklist 전부)`)을 따른다 — 이 표가 PASS여도 같은 산출물의 Gate나 Verification이 WARN/FAIL이면 전체 최종 판정은 그 WARN/FAIL이다(외부 검수 M-05/G-06).

| 판정 | 기준 |
|---|---|
| PASS | PK, 관계, 필수값, 유일성, 상태값·전이, 삭제 방식 선택, 시간 정책, 금액·수량 기준이 모두 확인됨 |
| 일반 WARN | 설명이나 인덱스 후보가 일부 부족하지만 핵심 데이터 손상 위험은 낮음 |
| 구조 WARN | 문서 연결, 산출물 소유권, 번호 체계, 인계 기준이 일부 모호해 추가 근거 확인 또는 사용자 확인이 필요함 |
| 위험 WARN | 관계, 상태값, 삭제 정책, 금액 기준 중 일부가 불명확해 사용자 확인 또는 추가 근거 전 진행 금지 |
| FAIL | PK 없음, 관계 설명 없음, 필수값 없음, 유일성 없음, 상태값·전이 기준 없음, 삭제 방식(Soft/Hard) 선택 안 됨, 시간 컬럼 기준 없음, 금액·수량 의미 불명확 |

Checklist 판정 칸에는 `PASS`, `WARN`, `FAIL` 중 하나를 쓰고, WARN인 경우 Report에 `일반 WARN`, `구조 WARN`, `위험 WARN` 중 하나를 함께 적는다.

Checklist 결과는 `06.REPORT_TEMPLATE.md`의 Checklist 결과 섹션에 옮긴다.
