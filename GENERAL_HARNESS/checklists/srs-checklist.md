### 0-1. SRS Context Pack 우선순위

SRS 문서가 원본, 추출본, 요약본, 색인, 후보 메모로 나뉘어 있으면 아래 순서를 따른다.

| 우선순위 | 문서 유형 | 처리 |
|---:|---|---|
| 1 | 사용자 또는 프로젝트가 확정한 원본 SRS | 최종 Source of Truth |
| 2 | 원본에서 추출한 확정 SRS 추출본 | 원본과 충돌하면 원본 우선 |
| 3 | SRS 요약본 또는 색인 | 탐색 보조. 원본을 대체하지 않음 |
| 4 | 후보 요구사항, 임시 메모 | 확정 전 구현 기준으로 사용하지 않음 |
| 5 | Deprecated 요구사항 | 현재 구현 기준에서 제외하고 대체 요구사항을 확인 |

| 문서 관계 | 우선 기준 |
|---|---|
| 원본 SRS와 추출본/요약본/색인이 다름 | 원본 SRS 우선 |
| 원본 SRS와 실제 구현 범위가 다름 | 차이를 Report에 기록하고 사용자 확인 |
| 후보 요구사항과 확정 요구사항이 다름 | 확정 요구사항 우선 |
| Deprecated 요구사항이 남아 있음 | 현재 구현 기준으로 사용하지 않고 대체 요구사항을 확인 |

SRS 요약본이 없는 것은 오류로 보지 않는다. 단, 요약본·색인·추출본을 기준으로 구현할 때는 원본 SRS와의 관계를 Report에 남긴다.

## 2. FAIL 기준

- 요구사항 ID 중복
- 현재 릴리즈/다음 릴리즈 범위 없음
- 상세 설명이 비어 있음
- 기능명만 있고 구현 기준이 없음
- 수용 기준이 없어 "완료" 여부를 판단할 수 없음
- 예외/실패 상황이 전혀 적혀 있지 않음(단순 조회처럼 예외가 실질적으로 없는 경우는 N/A와 근거로 대체 가능)

## 결과 요약

> 이 표는 **이 Checklist 자체의 판정**이다. 산출물 전체의 최종 판정은 `08.QUALITY_GATE.md §7-2`의 전역 공식(`maxSeverity(Verification, 적용 Gate 전부, 적용 Checklist 전부)`)을 따른다 — 이 표가 PASS여도 같은 산출물의 Gate나 Verification이 WARN/FAIL이면 전체 최종 판정은 그 WARN/FAIL이다(외부 검수 M-05/G-06).

| 판정 | 기준 |
|---|---|
| PASS | 요구사항 ID, 범위, 우선순위, 상세 설명, 수용 기준, 입력/출력, 예외/실패, 검증 방법이 모두 확인되거나 근거 있는 N/A로 처리됨 |
| 일반 WARN | 설명이나 비고가 일부 부족하지만 구현 범위와 핵심 조건은 판단 가능함 |
| 구조 WARN | 문서 연결, 산출물 소유권, 번호 체계, 인계 기준이 일부 모호해 추가 근거 확인 또는 사용자 확인이 필요함 |
| 위험 WARN | 범위나 우선순위가 모호해 사용자 확인 또는 추가 근거가 필요함 |
| FAIL | 요구사항 ID 중복, 범위 없음, 상세 설명 없음, 구현 기준 없음, 수용 기준 없음, 예외/실패 상황이 전혀 없음(N/A와 근거로 대체된 경우 제외) |

Checklist 판정 칸에는 `PASS`, `WARN`, `FAIL` 중 하나를 쓰고, WARN인 경우 Report에 `일반 WARN`, `구조 WARN`, `위험 WARN` 중 하나를 함께 적는다.

Checklist 결과는 `06.REPORT_TEMPLATE.md`의 Checklist 결과 섹션에 옮긴다.
