## 2. FAIL 기준

- Request/Response 없음
- 실패 응답 없음
- 인증/권한 기준 없음
- URL이 동사 중심으로 과하게 설계됨

## 결과 요약

> 이 표는 **이 Checklist 자체의 판정**이다. 산출물 전체의 최종 판정은 `08.QUALITY_GATE.md §7-2`의 전역 공식(`maxSeverity(Verification, 적용 Gate 전부, 적용 Checklist 전부)`)을 따른다 — 이 표가 PASS여도 같은 산출물의 Gate나 Verification이 WARN/FAIL이면 전체 최종 판정은 그 WARN/FAIL이다(외부 검수 M-05/G-06).

| 판정 | 기준 |
|---|---|
| PASS | 필수 항목이 모두 확인되었고 위험한 누락이 없으며 계약 상태가 표시됨 |
| 일반 WARN | 설명, 예시, 필드 설명이 일부 부족하지만 핵심 요청/응답/실패/권한 기준은 있음 |
| 구조 WARN | 문서 연결, 산출물 소유권, 번호 체계, 인계 기준이 일부 모호해 추가 근거 확인 또는 사용자 확인이 필요함. 계약 상태 표시 누락도 이미 구현에 쓰인 흔적이 없다면 여기에 해당함 |
| 위험 WARN | 인증/권한/실패 응답 기준이 약해 사용자 확인 또는 추가 근거가 필요함 |
| FAIL | Request/Response, 실패 응답, 인증/권한 기준 중 핵심 항목이 없음. 또는 `Confirmed` 상태 계약을 영향 범위 확인 없이 수정함 |

Checklist 판정 칸에는 `PASS`, `WARN`, `FAIL` 중 하나를 쓰고, WARN인 경우 Report에 `일반 WARN`, `구조 WARN`, `위험 WARN` 중 하나를 함께 적는다.

Checklist 결과는 `06.REPORT_TEMPLATE.md`의 Checklist 결과 섹션에 옮긴다.
