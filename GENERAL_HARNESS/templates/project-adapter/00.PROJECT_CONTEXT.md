# Project Context — 교체용 예시

## 책임과 기준 문서

제품 이름과 목표를 입력하고 아래 자리표시자를 실제 프로젝트 값으로 교체한다.

| 기준 문서 경로 | 소유자 | 책임 |
|---|---|---|
| {requirements-path}.md | {requirements-owner} | 제품 요구사항 |
| {ui-path}.md | {ui-owner} | 화면 계약 |

## 작업별 읽기 순서

ui 작업: 요구사항 → 화면 계약. manifest.json의 routes와 일치시킨다.
실제 작업 유형별 route를 추가하고 관계없는 문서는 로딩하지 않는다.

## 충돌과 갱신

기준 문서 누락·상충 시 해당 작업을 멈추고 담당자와 최신 사용자 요청으로 기준을 확정한다. 제품 규칙은 공통 하네스의 안전·작업 통제 규칙을 덮어쓰지 않는다. manifest.json에 원본 커밋, 어댑터 버전과 로컬 변경 내역을 함께 갱신한다.
