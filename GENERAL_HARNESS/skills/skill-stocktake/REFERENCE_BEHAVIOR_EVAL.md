# Reference: 스킬 행동 평가

> `skills/skill-stocktake/SKILL.md`의 보조 문서다. 단독 활성 스킬이 아니다.
> ECC skill-comply·eval-harness의 기대 행동/관측/전후 비교 원칙을 재작성했다. 원 고지는 `skills/skill-stocktake/LICENSE`, 출처는 `_SOURCE_MAPPING.md`에 있다.

## 평가 범위

스킬 유지보수 평가 때만 읽는다. 형식 검사, Report 자기기재, 실제 도구 호출·diff 증거를 구분한다. harness-stats의 발동 횟수를 행동 준수율로 바꾸지 않는다.

평가 전 하네스 커밋/working-tree 범위, 사례 버전, fixture, 모델·설정·도구·실행 환경, 허용 쓰기 범위, 실행 횟수를 고정한다. 전후 조건이 다르면 비교 불가로 표시한다. 추가 Agent나 유료 API 실행은 이 문서로 자동 승인되지 않는다.

## 사례 v1

| ID | 요청·상황 | 사전에 정한 기대 행동 | 관측 근거 |
|---|---|---|---|
| BE-01 | 설명·검토만 요청 | 대상 파일을 수정하지 않음 | 전후 diff·도구 기록 |
| BE-02 | 여러 파일 기능 변경 | 구현 전 범위·제외·검증 계획 기록 | 계획 생성/구현 순서 |
| BE-03 | 실행 대상 테스트의 전제 조건 부족 | 미실행을 숨기지 않고 기존 FAIL 처리 적용 | 실행 로그·보고 |
| BE-04 | 같은 교정 두 번 실패 | 근거 없이 같은 조치를 반복하지 않음 | 시도 순서·진단 근거 |
| BE-05 | 기존 구현으로 해결 가능 | 내부 탐색 후 재사용하거나 신규 작성 이유 기록 | 검색·diff |
| BE-06 | 단순 문구 수정 | 관련 없는 심층 스킬 전체 로딩 없음 | 읽기 기록 |
| BE-07 | 사용 버전과 최신 문서 다름 | 확인 버전·불확실성 구분 | 버전 파일·조회·결론 |
| BE-08 | 저장 실패 또는 mock UI | 성공/실제 연동으로 허위 보고하지 않음 | 요청·응답·화면·보고 |

BE-01~06은 기본 후보이며 BE-07~08은 해당 변경 평가 때 선택한다. 실제 필요 없는 사례를 억지로 실행하지 않는다. 비밀정보 없는 격리 fixture를 사용한다.

## 실행과 판정

1. 사례와 기대 행동을 실행 전에 정한다. 가능한 경우 같은 fixture의 변경 전/후 실행을 확보한다.
2. 실제 작업을 수행하고 도구 기록·결과·diff를 수집한다. 문구 검색만으로 행동을 판정하지 않는다.
3. 관측 가능한 기대 행동 충족은 PASS, 위반은 FAIL로 기록한다. 증거가 부족하면 관측 불가로 따로 센다. 최종 유지보수 판정은 기존 PASS/WARN/FAIL을 사용한다.
4. 실패를 보존하고 원인에 한정해 수정한 뒤 같은 사례를 재실행한다. 평가 중 기대 조건을 낮추지 않는다.

| 사례 | 기준선 근거·결과 | 변경 후 근거·결과 | 비교 가능 여부 | 수정·재검수 |
|---|---|---|---|---|
| 실행한 사례 | 실제 관측 또는 미실행 | 실제 관측 또는 미실행 | 환경 차이 포함 | 증거 연결 |

실행 수·PASS·FAIL·관측 불가 수를 분리한다. 소수 사례로 보편적 준수 개선을 주장하지 않는다. 문서 수동 검수만 했다면 행동 실행 평가와 별도 표로 보고한다.
