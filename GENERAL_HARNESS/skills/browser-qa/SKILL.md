# Browser QA

> 목적: UI 구현·수정 후 실제 브라우저(자동화 도구)에서 치수·상태·접근성 수치를 측정해, 다음 세션이 같은 검증을 재현할 수 있는 형태로 기록한다.
> 사용 위치: `GENERAL_HARNESS` 공통 스킬 (코드 스킬). 특정 브라우저 자동화 도구(MCP, 확장 등)를 전역으로 고정하지 않으며, 사용한 도구를 그때그때 기록한다.
> 출력물: 도구·뷰포트·측정 명령·측정값이 포함된 재현 가능한 검증 기록

---

## 0. Harness Control Rule

- 이 스킬은 `00.HARNESS_RULES.md`의 하위 모듈이다.
- 충돌 시 이 스킬의 절차를 중단하고 `00.QUICK_REF.md`와 `00.HARNESS_RULES.md §3` 우선순위에 따라 상위 규칙을 따른다. 위험 작업 WARN은 사용자 확인 전 스킬 단독으로 진행하지 않는다.

---

## 1. Trigger

- UI 구현·수정 완료 보고 전, 실제 브라우저에서 동작·치수·상태를 측정해 확인할 때
- 뷰포트별(모바일/PC) 레이아웃 회귀를 확인할 때
- 색상 대비, 터치 영역 크기, 포커스 이동 같은 접근성 수치를 실측할 때
- `gates/ui-ux-gate.md` 판정에 실측 근거가 필요할 때

---

## 2. Do Not Trigger

- 브라우저 자동화 도구를 사용할 수 없는 환경인 경우(이때는 `skills/verification-loop/SKILL.md`의 수동 검증으로 처리하고, 수동 확인이었음을 기록)
- 문서·백엔드 전용 작업으로 화면 산출물이 없는 경우
- 시각 품질의 주관적 판단만 필요한 경우(그건 `skills/ui-ux-design/SKILL.md`의 검토 절차가 소유)

---

## 3. Required Inputs

| 입력물 | 필요 이유 |
|---|---|
| 실행 중인 앱 주소 또는 빌드 산출물 | 측정 대상 |
| 검증할 완료 기준(관찰 가능한 결과) | 무엇을 측정할지 결정 |
| 사용할 자동화 도구 이름 | 재현 기록의 필수 요소 |

---

## 4. Procedure

1. **도구 명시**: 사용하는 자동화 도구(예: 브라우저 MCP, 확장)를 기록한다. "Browser" 같은 미등록 명칭으로 적지 않는다 — 스킬명은 `browser-qa`, 도구명은 실제 도구 이름으로 적는다.
2. **뷰포트 정의**: 확인할 뷰포트를 px 단위로 정한다(예: 375, 390, 1280). "모바일에서 확인함"처럼 수치 없는 표현을 쓰지 않는다.
3. **측정**: 완료 기준에 해당하는 값을 실측한다 — 치수(`scrollWidth`/`clientWidth` 등), 상태(`aria-expanded` 등), 색상 대비 비율, 터치 영역 크기, 스크롤/오버플로 여부.
4. **재현 기록**: 기능·데이터·세션 변경이면 테스트 준비 상태, 사용자 행동, 관측 가능한 요청/응답, 화면 전이, 재조회 결과를 함께 남긴다. 네트워크 관측 불가는 그대로 표시하고 mock/실제/수동 확인을 구분한다. `checklists/ui-ux-checklist.md §1-3`이 기능 검수 기준을 소유하며, 이 스킬의 관측 기록 PASS가 업무 동작 PASS를 뜻하지 않는다. 도구명, 뷰포트 px, 측정에 사용한 명령·스크립트·속성명, 측정값을 함께 기록한다. 기준: 다음 세션이 이 기록만 보고 같은 측정을 다시 할 수 있어야 한다.
5. **판정 인계**: 측정 결과를 `skills/verification-loop/SKILL.md`의 검증 항목으로 넘기고, UI 작업이면 `gates/ui-ux-gate.md` 판정 근거로 사용한다.

---

## 5. Quality Gate

| 판정 | 기준 |
|---|---|
| PASS | 도구명·뷰포트 px·측정 수단·측정값이 모두 기록되어 제3자가 같은 검증을 재현할 수 있음 |
| WARN | 측정은 수행했으나 재현 정보 일부(도구명 또는 뷰포트 수치)가 누락됨 — 보완 전 완료 보고하지 않음 |
| FAIL | 수치·수단 없이 "확인함"만 기록됨, 또는 미등록 명칭("Browser" 등)으로 스킬 적용을 기록함 |

---

## 6. Output Format

```md
## Browser QA 결과

- 사용 도구:
- 뷰포트(px):
- 측정 항목과 값:
  - [항목]: [측정 수단] → [값] (기준: [완료 기준])
- PASS/WARN/FAIL:
- 다음 연결:
```

---

## 7. Handoff

다음 연결: `skills/verification-loop/SKILL.md`(검증 항목 통합) → `gates/ui-ux-gate.md`(UI 작업 시) → `06.REPORT_TEMPLATE.md`

---

## 8. Anti-Patterns

- 적용 스킬을 "Browser" 등 미등록 명칭으로 기록하기(실사용 검수 P-03 — 5회 발생한 실제 사례)
- 수치 없이 "모바일에서 정상 표시됨"으로 보고하기 — `npm run build`는 재현되지만 "390px에서 확인함"은 재현되지 않는다
- 특정 자동화 도구 이름을 하네스 전역 기본값으로 고정하기(도구는 프로젝트·세션마다 다를 수 있다)
- 자동화 도구 없이 수동으로 확인하고 이 스킬을 적용했다고 기록하기(그 경우는 `skills/verification-loop/SKILL.md` 수동 검증으로 기록)
