# Interaction States

> `skills/vue-ui-polish/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule(Vue 3 스택 한정 포함)을 그대로 따른다.

모든 컴포넌트에 기계적으로 같은 상태 수를 강요하지 말고, 기능 계약에 적용되는 상태를 빠짐없이 구현하라.

## 공통 입력 상태

| 상태 | 확인할 내용 |
| --- | --- |
| default | 역할과 주요 행동이 보이는가 |
| hover | PC 포인터의 보조 피드백인가, 정보의 유일한 통로는 아닌가 |
| focus-visible | 키보드 위치가 즉시 보이는가 |
| active | 입력이 접수됐음을 짧게 보여주는가 |
| disabled | 비활성 이유가 주변 문맥이나 설명으로 전달되는가 |

## 비동기 상태

| 상태 | 확인할 내용 |
| --- | --- |
| idle | 중복 요청이 없는 정상 상태 |
| loading | 대상과 진행 중임을 알리고 중복 실행을 막는가 |
| success | 결과가 화면에 반영되고 다음 행동이 보이는가 |
| error | 무엇이 실패했고 무엇을 유지했는지, 어떻게 복구하는지 보이는가 |

`success`가 이미 화면에 명확히 보이면 축하 토스트를 중복으로 띄우지 않는다. 오류가 입력 필드와 관련 있으면 필드 가까이에 연결하고 요약만 전역에 둔다.

## 오버레이 상태

모달·드로어·팝오버·메뉴는 다음을 확인한다.

- 열기 전 포커스를 기억한다.
- 열린 뒤 첫 유효 요소 또는 컨테이너로 포커스를 옮긴다.
- Escape와 명시적 닫기 수단을 제공한다.
- 닫힌 뒤 트리거로 포커스를 되돌린다.
- 배경 스크롤과 포커스 이동을 맥락에 맞게 제한한다.
- 모바일 키보드와 safe area에 가려지지 않는다.

## 목록 상태

- 안정적이고 고유한 `key`를 사용한다.
- 로딩 중 기존 데이터를 유지할지 비울지 의도적으로 결정한다.
- 빈 결과와 아직 생성하지 않은 빈 상태를 구분한다.
- 정렬·필터 변경 후 초점과 스크롤 위치가 예측 가능해야 한다.
- 낙관적 업데이트가 실패하면 되돌림과 설명을 제공한다.

## 상태 구현 원칙

- 서버 상태와 단순 시각 상태를 같은 boolean에 섞지 않는다.
- `isLoading`, `error`, `data`의 불가능한 조합이 생기면 명시적 상태 모델을 고려한다.
- 색상만으로 상태를 구분하지 않는다.
- loading 중 버튼 폭이 바뀌어 레이아웃이 흔들리지 않게 한다.
- 비활성 버튼만 보여주고 이유를 숨기기보다, 가능하면 필요한 조건을 설명한다.
