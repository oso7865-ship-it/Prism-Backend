# Quality Gates

> `skills/vue-ui-polish/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule(Vue 3 스택 한정 포함)을 그대로 따른다.

아래 순서대로 검사한다. 앞 단계가 실패하면 뒤의 장식적 개선으로 덮지 말고 먼저 수정한다.

## P0 기능과 데이터

- 핵심 행동이 실제로 완료되는가
- 로딩·성공·실패·빈 상태가 데이터 흐름과 일치하는가
- 중복 제출, 경합, 새로고침 후 복구가 깨지지 않는가
- 디자인 변경이 API·인증·라우트 계약을 훼손하지 않았는가

하나라도 실패하면 출시 차단이다.

## P1 사용자 이해

- 2초 안에 화면 목적과 주요 행동을 알 수 있는가
- 금액, 대상, 상태, 위험 행동을 오해할 가능성이 없는가
- 오류 뒤 복구 경로가 보이는가
- 빈 상태에서 다음 행동을 알 수 있는가

## P2 접근성

- 의미 있는 HTML, 키보드 조작, focus-visible이 동작하는가
- 색상 대비와 비색상 상태 표지가 있는가
- 오버레이 포커스와 reduced motion이 처리됐는가
- 확대·화면 읽기 순서·접근 가능한 이름이 적절한가

## P3 시스템 일관성

- 기존 토큰과 공통 컴포넌트를 재사용했는가
- Tailwind, scoped CSS, CSS Modules 방식을 불필요하게 혼합하지 않았는가
- 같은 의미의 버튼·상태·간격이 화면마다 달라지지 않는가
- PrimeVue를 사용한다면 프로젝트의 테마·unstyled·PassThrough 방식을 따르는가

## P4 반응형과 성능

- 320·375·414·768px와 대표 PC 너비에서 가로 넘침이 없는가
- 터치 대상, 모바일 키보드, safe area가 적절한가
- 긴 텍스트와 데이터가 레이아웃을 깨뜨리지 않는가
- 불필요한 의존성, 레이아웃 애니메이션, 큰 이미지가 없는가

## P5 시각적 구체성

- 이 화면이 다른 제품의 문구로 바꿔도 그대로인 템플릿은 아닌가
- 실제 중요도에 따라 위계와 밀도가 달라지는가
- 카드·pill·그라데이션·중앙 정렬이 목적 없이 반복되지 않는가
- 한 가지 중심 선택이 제품 과업을 설명하는가
- 같은 앱에서는 시스템이 일관되고, 다른 과업에서는 구조가 필요한 만큼 달라지는가
- 선언한 세 다이얼이 실제 구조·모션·정보량과 일치하는가
- display 서체와 팔레트가 “프리미엄처럼 보이기 위한 기본 세트”가 아니라 브랜드·콘텐츠 근거를 가지는가
- 강조색과 모서리 체계가 페이지 중간에 이유 없이 바뀌지 않는가
- 여러 섹션이 같은 제목·카드·CTA 골격을 복사하지 않는가

P5 경고는 맥락을 검토한 뒤 허용할 수 있다. 허용 이유를 한 문장으로 기록한다.

## P6 모션

- 각 모션이 피드백·공간 연결·상태·설명 중 하나를 수행하는가
- 빈번한 작업을 느리게 만들지 않는가
- `transition: all`, layout property 애니메이션, hover-only 정보가 없는가
- 빠른 반복 조작과 reduced motion에서 깨지지 않는가

## 자동 검사

정적 검사는 후보를 찾는 도구다.

```bash
node skills/vue-ui-polish/scripts/ui-pattern-audit.mjs src
node skills/vue-ui-polish/scripts/ui-pattern-audit.mjs src/components/Foo.vue src/pages/Bar.vue
```

경고가 나왔다고 자동으로 코드를 바꾸지 않는다. 실제 역할과 기존 디자인 시스템을 확인한다.
