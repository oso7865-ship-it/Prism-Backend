# Taste Strategy

> `skills/vue-ui-polish/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule(Vue 3 스택 한정 포함)을 그대로 따른다.

시각적 새로움보다 브리프 적합성을 먼저 판단하라. 이 문서는 새 페이지, 브랜드·마케팅 화면, 시각 범위가 큰 재설계에서만 읽는다. 작은 컴포넌트 수정, 버그 수정, 단순 상태 추가에는 적용하지 않는다.

## 1. 디자인 해석

코드보다 먼저 다음 신호를 읽고 한 문장으로 정리한다.

- 화면 종류: 작업 앱, 탐색·커머스, 랜딩, 포트폴리오, 편집 콘텐츠, 재설계
- 사용자와 과업: 누가 무엇을 끝내야 하는가
- 분위기 단어와 참고 자료: 사용자가 실제로 말하거나 제공한 것
- 기존 자산: 로고, 색상, 글꼴, 사진, 컴포넌트, 문구
- 조용한 제약: 접근성, 신뢰, 규제, 공공성, 성능, 모바일 비중

형식은 다음처럼 짧게 유지한다.

```text
디자인 해석: <화면 종류>를 사용하는 <사용자>가 <핵심 과업>을 끝내는 화면. <분위기>를 따르되 <제약>을 우선한다.
```

구현 전에 내부 판단으로 작성한다. 대규모 신규 제작·전면 재설계에서 선택 비용이 클 때만 사용자에게 보여준다. 해석이 두 방향으로 크게 갈리면 질문은 하나만 한다.

## 2. 세 다이얼

세 값을 1-10으로 정하고 시각 결정의 강도를 맞춘다. 값은 목표가 아니라 제한 장치다.

| 다이얼 | 낮은 값 | 높은 값 |
| --- | --- | --- |
| `DESIGN_VARIANCE` | 대칭, 익숙한 배치, 높은 학습 가능성 | 비대칭, 혼합 비율, 실험적 흐름 |
| `MOTION_INTENSITY` | 정적, 상태 피드백 중심 | 공간 연결, 스크롤 서사, 물리감 |
| `VISUAL_DENSITY` | 여백이 많고 한 가지 메시지 | 한 화면에 많은 정보와 조작 |

다음은 출발점일 뿐이며 기존 시스템과 콘텐츠가 우선한다.

| 맥락 | VARIANCE | MOTION | DENSITY |
| --- | ---: | ---: | ---: |
| 작업 중심 제품 화면 | 3-5 | 2-4 | 5-8 |
| 탐색·커머스 | 5-7 | 3-5 | 5-7 |
| 일반 랜딩·포트폴리오 | 6-8 | 4-6 | 3-5 |
| 편집·콘텐츠 | 5-7 | 2-4 | 3-5 |
| 공공·규제·신뢰 우선 | 2-4 | 1-3 | 4-6 |
| 기존 화면 polish | 현재 값 유지 | 필요한 축만 +1 | 현재 값 유지 |
| redesign | 현재 값을 측정 | 승인된 범위만 변경 | 과업에 맞춰 유지 |

다이얼이 높다고 모든 요소를 특이하게 만들지 마라. `DESIGN_VARIANCE`는 주요 구조 한두 곳, `MOTION_INTENSITY`는 의미 있는 전환, `VISUAL_DENSITY`는 정보 우선순위에 반영한다.

## 3. 타입 규율

- 읽기와 브랜드 근거를 먼저 확인한다. Inter, system font, 명조체를 이름만으로 실패시키지 않는다.
- 현대적·프리미엄·창의적이라는 이유만으로 명조 display를 선택하지 않는다.
- 제목 강조는 다른 글꼴을 끼우기 전에 같은 가족의 굵기·폭·이탤릭으로 해결한다.
- 한글에서는 실제 한글 자형, 숫자, 영문 혼용, 필요한 굵기, 라이선스와 로딩 성능을 확인한다.
- 큰 제목은 고정 줄 수가 아니라 320px 모바일에서 의미 단위와 CTA 노출을 기준으로 조정한다.
- 기존 브랜드 글꼴이 있으면 교체보다 사용 방식과 위계를 먼저 개선한다.

## 4. 팔레트와 형태 규율

- 한 화면의 강조색은 원칙적으로 하나의 의미 체계로 잠근다. success·warning·danger 같은 상태색은 예외다.
- 따뜻한 크림 배경 + 점토·황동 강조 + 갈색 본문을 프리미엄의 기본 공식으로 사용하지 않는다.
- 대안은 브랜드와 상품에 맞춰 차가운 중성색, 숲 계열, 흑백 대비, 코발트, 올리브·벽돌색, 단색+선명한 포인트 등에서 고른다. 목록을 순환 규칙으로 쓰지 않는다.
- 모서리는 의미 있는 단계로 제한한다. 예: 입력 8px, 카드 12px, 선택형 chip pill. 규칙 없이 둥근 것과 각진 것을 섞지 않는다.
- 그림자보다 간격·헤어라인·배경 단계로 먼저 위계를 만든다.

## 5. 구조 반복 방지

- 중앙 영웅 영역, 동일 크기 3열 카드, 로고 벽, CTA, 푸터를 자동 순서로 만들지 않는다.
- 6개 이상의 섹션에서는 콘텐츠 목적이 다른데도 같은 구조 가족이 세 번 이상 연속되지 않게 한다.
- 마케팅 화면은 실제 증거·데모·과정·상품 탐색을 중심으로 순서를 만든다.
- 제품 화면은 익숙한 폼·표·탐색 패턴을 유지하고, 헤더·밀도·예외 처리에서 개성을 만든다.
- 무작위 선택, 프롬프트 글자 수, 이전 결과와 다르게 보이기 같은 기준으로 레이아웃을 결정하지 않는다.

## 6. 모션 경계

- 정적인 화면을 실패로 간주하지 않는다. 상태와 공간 관계가 명확하면 정적 구성이 더 낫다.
- 기존 프로젝트에 없는 GSAP·Motion·애니메이션 라이브러리를 시각적 야심만으로 추가하지 않는다.
- `MOTION_INTENSITY`가 4 이상이면 실제 모션과 reduced-motion 대안을 함께 구현한다.
- 스크롤 고정·가로 이동·자석 효과는 콘텐츠 이해를 개선하고 모바일 대안이 있을 때만 사용한다.
- 빈번한 제품 작업에는 영화적 전환보다 즉각적인 피드백을 우선한다.

## 7. 리디자인 경계

- 보존형과 전면 개편형을 구분하고 모호하면 한 번만 묻는다.
- 보존형에서는 타입, 간격, 중성색, 상태 피드백 순으로 위험이 낮은 개선부터 적용한다.
- URL, 탐색 명칭, form field 이름, 분석 이벤트, SEO 메타데이터, 법적 문구, 브랜드 워드마크를 조용히 바꾸지 않는다.
- 공식 디자인 시스템을 이미 사용하는 프로젝트는 해당 패키지와 토큰을 사용한다. 새로운 시스템을 섞거나 프레임워크를 교체하지 않는다.

## 8. 의도적으로 편입하지 않은 규칙

다음은 항상 적용되는 제품 UI 규칙으로 사용하지 않는다.

- AIDA를 모든 페이지의 고정 구조로 강제하기
- GSAP·거대한 여백·스크롤 고정을 기본값으로 강제하기
- 제목을 무조건 2-3줄로 제한하기
- 문장부호, 특정 아이콘 라이브러리, 특정 글꼴을 전면 금지하기
- 난수나 모의 스크립트로 디자인을 선택하기
- 과거 결과와 다르게 보이는 것 자체를 품질로 판단하기

이 스킬의 판단 우선순위와 기존 Vue 프로젝트 규칙이 언제나 이 문서보다 앞선다.
