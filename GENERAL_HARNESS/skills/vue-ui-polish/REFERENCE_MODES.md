# Modes

> `skills/vue-ui-polish/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule(Vue 3 스택 한정 포함)을 그대로 따른다.

사용자의 요청이 허용한 범위만 수행하라. 모드를 고른 뒤 다른 모드로 몰래 확장하지 마라.

## Build

새 화면이나 컴포넌트를 실제로 구현한다.

1. 기존 프로젝트와 디자인 시스템을 조사한다.
2. 사용자·핵심 과업·필수 상태를 복원한다.
3. 모바일 기준 와이어프레임을 잡는다.
4. 구조와 토큰을 결정한다.
5. 기존 Vue 관례로 구현한다.
6. 제품 검수와 시각 검수를 모두 통과시킨다.

간단한 단일 컴포넌트라면 페이지 구조·영웅 영역·테마 선택을 생략한다.

## Audit

진단만 수행하고 코드를 수정하지 않는다.

- 첫 번째 패스: 기능, 사용자 흐름, 상태, 접근성, 반응형
- 두 번째 패스: 토큰, 위계, 반복 구조, 템플릿성, 모션
- 파일과 줄을 확인할 수 있으면 정확한 위치를 제시한다.
- 자동 검사 결과를 그대로 판정하지 말고 실제 맥락을 확인한다.
- 문제 수를 채우지 않는다. 적절한 부분은 적절하다고 말한다.

## Polish

기존 정보 구조·라우트·컴포넌트 소유권·비즈니스 로직을 보존하는 최소 수정 모드다.

- 레이아웃, 밀도, 위계, 상태 표현, 피드백, 모션을 작은 단위로 개선한다.
- 공통 컴포넌트로 해결할 수 있으면 페이지별 CSS를 늘리지 않는다.
- 전면 재설계가 필요해 보여도 사용자가 요청하지 않았다면 진단과 제안까지만 한다.

## Redesign

콘텐츠 의도와 기능은 유지하면서 구조적 인상을 바꾼다.

수정 전에 현재 상태를 짧게 감사한다.

- 브랜드 토큰: 색상, 타입, 로고, 모서리, 아이콘, 상태 언어
- 정보 구조: 라우트, 탐색, 핵심 과업과 전환 경로
- 보존할 자산: 잘 작동하는 컴포넌트, 상호작용, 문구, 접근성 처리
- 교체 후보: 반복 구조, 토큰 이탈, 죽은 링크, 성능 병목, 가짜 콘텐츠
- 외부 계약: URL, anchor·field 이름, 분석 이벤트, SEO·OG 메타데이터

사용자가 명시하지 않으면 외부 계약과 브랜드 워드마크를 바꾸지 마라. 현재 화면의 `DESIGN_VARIANCE`, `MOTION_INTENSITY`, `VISUAL_DENSITY`를 출발점으로 읽고, 개선을 이유로 임의의 기본값으로 되돌리지 마라.

### 단일 화면

- 보존: 사실, 핵심 메시지, 주요 행동, 데이터 흐름, 라우트 경계
- 변경 가능: 정보 묶음, 제목 배치, 콘텐츠 밀도, 구분 방식, 컴포넌트 표현
- 확인 필요: 다수 컴포넌트 삭제, 라우트 트리 변경, 비즈니스 로직 재작성

### 다중 화면

먼저 공통 시스템을 잠근다.

1. 화면 목록과 각 과업을 정리한다.
2. 기존 `DESIGN.md`, 토큰, 공통 컴포넌트를 확인한다.
3. 색상·타입·간격·상태·CTA·모션 언어를 하나로 고정한다.
4. 페이지 유형별로 허용할 구조 가족을 정한다.
5. 시스템을 확인받아야 하는 중요한 판단이 있으면 구현 전에 한 번만 묻는다.
6. 각 화면은 같은 시스템 안에서 과업에 맞는 밀도와 구성만 달리한다.

페이지마다 다른 테마를 부여하지 마라. 같은 제품에서는 일관성이 다양성보다 우선한다.

## Study

참고 화면의 픽셀을 복제하지 않고 재사용 가능한 원리를 추출한다.

다음을 분리해 보고한다.

- 정보 구조와 주요 행동
- 콘텐츠 밀도와 시선 흐름
- 제목·본문·보조 정보의 관계
- 색상 역할과 대비
- 컴포넌트 표현과 구분 방식
- 모션의 목적과 빈도
- 그대로 가져오면 안 되는 브랜드 고유 요소

결과는 사용자의 제품 내용으로 다시 설계할 수 있는 원칙이어야 한다. 유료 템플릿이나 타인의 고유 화면을 복제하지 마라.
