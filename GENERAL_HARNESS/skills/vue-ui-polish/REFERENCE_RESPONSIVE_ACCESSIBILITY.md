# Responsive and Accessibility

> `skills/vue-ui-polish/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule(Vue 3 스택 한정 포함)을 그대로 따른다.

## 검증 너비

최소한 다음 너비를 확인한다.

- 320px: 가장 좁은 지원 화면
- 375px, 414px: 일반 모바일
- 768px: 태블릿·전환 구간
- 프로젝트의 대표 PC 너비: 보통 1280px 이상

CSS로 넘침을 숨기기 전에 원인을 수정한다. `overflow-x: hidden`이나 `clip`은 의도된 캔버스 효과가 아닌 레이아웃 버그를 가리는 용도로 사용하지 않는다.

## 레이아웃

- 모바일 단일 열에서 핵심 과업을 끝낼 수 있어야 한다.
- flex·grid 자식의 긴 텍스트에는 `min-width: 0`과 적절한 줄바꿈을 확인한다.
- 이미지가 있는 grid는 트랙 축소 가능 여부를 확인한다.
- `100vw`로 스크롤바 폭을 포함하지 말고 보통 `width: 100%`를 사용한다.
- 모바일 브라우저 높이와 상호작용하는 화면은 `dvh`·`svh`를 검토한다.
- 고정 하단 UI는 safe area와 소프트 키보드를 고려한다.
- 버튼 문구가 두 줄이 되면 폰트를 줄이기 전에 문구·부모 배치를 개선한다.

## 터치와 포인터

- 주요 터치 대상은 충분한 크기와 간격을 가진다.
- hover는 보조 피드백으로만 사용한다.
- PC 전용 hover 효과는 `(hover: hover) and (pointer: fine)` 조건을 고려한다.
- 드래그만 가능한 기능에는 버튼·키보드 대안을 제공한다.

## 키보드와 의미 구조

- 클릭 가능한 `div`보다 `button`, 이동은 `a`를 사용한다.
- 제목 단계와 landmark가 화면 구조를 반영한다.
- Tab 순서는 시각적 읽기 순서와 일치한다.
- `:focus-visible`은 배경과 충분히 구분되고 즉시 나타난다.
- 모달·메뉴·팝오버의 포커스 이동과 복귀를 확인한다.
- 아이콘 전용 버튼은 접근 가능한 이름을 가진다.

## 색상과 텍스트

- 본문, 큰 텍스트, 아이콘, 포커스, 상태의 대비를 각각 확인한다.
- 색상만으로 성공·경고·실패를 전달하지 않는다.
- 200% 확대에서도 핵심 기능과 내용이 손실되지 않아야 한다.
- 긴 한국어·영어·숫자·URL과 번역 확장에 견디는지 확인한다.
- 텍스트를 이미지에 포함하지 않는다. 브랜드 자산은 예외일 수 있다.

## 모션과 미디어

- `prefers-reduced-motion`에서 큰 이동·확대·시차를 줄인다.
- 상태 변화 자체를 제거하지 말고 opacity·색상·즉시 전환으로 보존한다.
- 자동 재생·회전 콘텐츠는 정지 수단과 포커스 시 정지를 제공한다.
- 이미지에 크기 정보를 제공해 레이아웃 이동을 줄인다.
- 장식 이미지는 보조 기술에서 제외하고, 정보 이미지는 목적에 맞는 대체 텍스트를 쓴다.
