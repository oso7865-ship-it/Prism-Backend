# Visual Strategy

> `skills/vue-ui-polish/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule(Vue 3 스택 한정 포함)을 그대로 따른다.

시각 전략은 제품 과업과 콘텐츠를 표현하는 방법이다. 콘텐츠를 정해진 템플릿에 끼워 맞추지 마라.

새 화면이나 재설계에서는 `skills/vue-ui-polish/REFERENCE_TASTE_STRATEGY.md`의 디자인 해석과 세 다이얼을 먼저 결정한다. 기존 화면의 작은 개선에서는 현재 시스템을 그대로 읽고 필요한 축만 조정한다.

## 1. 기존 시스템 우선

다음 순서로 소스를 선택한다.

1. 프로젝트의 `DESIGN.md` 또는 디자인 토큰
2. 공통 Vue 컴포넌트와 실제 화면에서 반복되는 패턴
3. 사용자가 제공한 브랜드·와이어프레임·참고 자료
4. 위 자료가 없을 때만 새 시스템 제안

같은 제품의 화면은 색상, 타입, 간격, 모서리, 상태, 아이콘, CTA 언어를 공유한다. 다양성은 브랜드를 바꾸는 것이 아니라 과업에 맞는 정보 구성에서 만든다.

## 2. 구조 지문

페이지 작업에서는 다음 축을 의식적으로 결정한다.

| 축 | 선택 예시 |
| --- | --- |
| 주요 행동 | 상단 고정, 본문 직후, 하단 요약, 컨텍스트 내부 |
| 제목 | 좌측 시작, 내용과 인라인, 중앙 집중, 패널 내부 |
| 본문 | 단일 열, 비대칭 2열, 작업대 분할, 밀집 표·목록 |
| 섹션 구분 | 간격, 헤어라인, 배경 단계, 제목 리듬 |
| 탐색 | 상단, 사이드 레일, 탭, 단계 진행, 검색 중심 |
| 시각 자료 | 없음, 실제 이미지, 데이터, 다이어그램, 절제된 장식 |

모든 축을 특이하게 만들 필요는 없다. 화면 목적을 가장 잘 설명하는 한 가지 중심 선택만 명확하면 된다.

## 3. 과업별 구조 가족

### 작업 중심 앱

- 입력·편집: 폼 흐름, 단계형, 작업대 분할
- 탐색·관리: 목록+상세, 필터 레일, 인덱스
- 현황 파악: 요약+근거 데이터, 예외 우선 대시보드
- 비교·선택: 표, 비대칭 비교, 추천 근거 중심

### 콘텐츠·마케팅

- 이야기·설명: 긴 문서, 내러티브 흐름
- 제품 증명: 실제 데모, 과정, 사례 중심
- 상품 탐색: 카탈로그, 큐레이션, 필터 중심
- 캠페인: 하나의 메시지와 하나의 시각적 중심 장치

앱 화면에 마케팅 영웅 영역을 붙이지 말고, 마케팅 화면에 관리 대시보드 밀도를 강요하지 마라.

## 4. 디자인 토큰

기존 토큰이 있으면 그대로 소비한다. 새 시스템이 필요하면 최소한 다음 역할을 정의한다.

- 배경·표면·본문·보조 본문·경계·강조·포커스 색상
- display·body·mono 글꼴 역할
- 간격 단계
- 모서리 단계
- 짧은·중간 모션 시간과 easing
- success·warning·danger·info 상태

컴포넌트 내부에서 임의 값을 반복하지 않는다. 한 번만 필요한 값까지 과도하게 토큰화하지 말고, 반복되거나 의미가 있는 값만 이름을 부여한다.

## 5. 구조 다양성과 제품 일관성

- 새 독립 브랜드·캠페인은 이전 결과와 다른 구조를 선택할 수 있다.
- 같은 앱의 여러 화면은 공통 시스템을 유지하고 과업 유형에 따라 구조만 달리한다.
- 같은 목적의 화면은 학습 가능성을 위해 동일한 패턴을 재사용한다.
- 색상만 바꾼 구조를 새로운 방향이라고 부르지 않는다.
- 다르게 보이기 위해 익숙한 폼·탐색·표 패턴의 사용성을 희생하지 않는다.

## 6. 시각 방향 미리보기

대규모 신규 제작이나 재설계에서 판단 비용이 크면 구현 전에 다음만 짧게 제시한다.

```text
목적: 사용자가 이 화면에서 끝낼 과업
해석: 화면 종류·사용자·분위기·제약
강도: DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY
구조: 선택한 구조와 주요 행동 위치
시스템: 보존할 토큰·컴포넌트
중심 선택: 이 화면을 고유하게 만드는 한 가지
제외: 의도적으로 사용하지 않을 장식이나 패턴
```

운영 파일을 여러 개 갈아엎는 선택이 아니라면 불필요하게 매 단계 승인을 기다리지 않는다.
