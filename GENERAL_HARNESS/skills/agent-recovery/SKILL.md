# Agent Recovery

> 목적: Agent가 같은 실패를 반복하거나, 토큰만 소모하며 진전이 없거나, 원래 요청에서 벗어났을 때 원인을 진단하고 안전하게 멈추거나 복구한다.
> 사용 위치: `GENERAL_HARNESS` 공통 스킬
> 출력물: 실패 진단 기록과 복구/중단 판정

---

## 0. Harness Control Rule

- 이 스킬은 `00.HARNESS_RULES.md`의 하위 모듈이다.
- 충돌 시 이 스킬의 절차를 중단하고 `00.QUICK_REF.md`와 `00.HARNESS_RULES.md §3` 우선순위에 따라 상위 규칙을 따른다. 위험 작업 WARN은 사용자 확인 전 스킬 단독으로 진행하지 않는다.

---

## 1. Trigger

- 같은 오류가 반복되거나 같은 도구 호출을 반복하고 있을 때
- 여러 번 시도했는데 진전이 없을 때
- 작업이 원래 요청 범위에서 벗어났다고 느껴질 때
- 파일/환경 상태가 예상과 다르다는 것이 확인됐을 때
- `skills/verification-loop/SKILL.md`에서 FAIL이 반복될 때

---

## 2. Do Not Trigger

- 첫 번째 시도에서 발생한 단순 오류로, 원인이 이미 명확한 경우
- 실패가 아니라 사용자의 요청 변경으로 방향이 바뀐 경우
- 이 스킬을 실행 자체를 자동으로 차단하는 용도로 쓰려는 경우(이 스킬은 진단 절차이며 자동 차단 Hook이 아니다)

---

## 3. Required Inputs

| 입력물 | 필요 이유 |
|---|---|
| 실패 시점의 오류 메시지 또는 증상 | 원인 분류의 출발점 |
| 직전 도구 호출/작업 순서 | 반복 패턴 확인 |
| 원래 작업 목표 | 방향 이탈 여부 판단 기준 |
| 현재까지 시도한 조치 | 같은 조치를 반복하지 않기 위함 |

---

## 4. Procedure

1. **실패 캡처**: 무엇을 하려고 했는지, 무슨 오류가 났는지, 몇 번 반복됐는지를 먼저 기록한다. 기록 없이 바로 재시도하지 않는다.
2. **분류**: 실패를 다음 중 하나로 분류한다 — 입력값/전제 오류, 도구/명령 자체의 문제, 환경/파일 상태 불일치, 요청 범위 이탈, 반복 루프.
3. **가설 확인과 최소 조치 판단**: 관측 사실 → 가설 → 가설을 구분할 최소 검사 → 결과를 기록한 뒤 교정한다. 분류에 맞는 가장 작은 교정 조치를 하나만 고른다. 여러 조치를 동시에 시도하지 않는다.
4. **위험 판단**: 교정 조치가 삭제/대량 수정/DB/보안/결제와 관련되면 스킬 단독으로 진행하지 않고 `04.GATEGUARD.md` 기준에 따라 중단하거나 사용자 확인을 받는다.
5. **재시도 제한**: 같은 조치가 2회 이상 실패하면 같은 방식으로 다시 시도하지 않는다. 대신 사용자에게 상황을 보고하고 판단을 요청한다.
6. **보고**: 캡처한 실패, 분류, 가설·구분 검사, 시도한 조치, 결과를 정리해 남긴다. 복구 후에는 원래 실패 조건을 같은 검증으로 다시 확인한다.

---

## 5. Quality Gate

| 판정 | 기준 |
|---|---|
| PASS | 실패 원인이 분류되었고, 최소 조치로 실제 복구되었거나, 더 이상 사용자 입력을 기다리지 않고 안전하게 종료됨(예: 작업 자체를 취소하기로 확정) |
| WARN | 원인은 분류했으나 완전히 복구되지 않았고, 사용자 확인을 기다리는 중단 상태임(재개 여부가 아직 결정되지 않음) |
| FAIL | 같은 조치를 근거 없이 반복하거나, 위험 작업 교정을 사용자 확인 없이 진행하려 함 |

"안전하게 중단됨"은 PASS와 WARN에 겹쳐 보일 수 있는데, 기준은 **사용자 입력을 계속 기다리는지 여부**다. 사용자 확인을 기다리는 중이면 WARN, 더 기다릴 필요 없이 종료가 확정됐으면 PASS다.

---

## 6. Output Format

```md
## Agent Recovery 결과

- 사용 이유:
- 실패 캡처(증상/반복 횟수):
- 분류:
- 시도한 최소 조치:
- 위험 WARN 여부:
- PASS/WARN/FAIL:
- 다음 연결:
```

---

## 7. Handoff

다음 연결(결과에 따라 분기): 최소 조치로 **실제 복구**됐으면 `skills/verification-loop/SKILL.md`(재검증) → `06.REPORT_TEMPLATE.md`. **작업 자체를 취소하기로 확정**했으면 재검증 대상이 없으므로 바로 `06.REPORT_TEMPLATE.md`(취소 사유 기록)로. **사용자 확인을 기다리는 중**(WARN)이면 다음 단계로 진행하지 않고 대기한다. 위험 조치가 필요하면 어느 경우든 `04.GATEGUARD.md`를 먼저 거친다.

---

## 8. Anti-Patterns

- 원인 분류 없이 같은 재시도를 반복하기
- 실패를 숨기고 부분적으로만 완료된 것을 완료로 보고하기
- 위험한 교정 조치를 사용자 확인 없이 바로 실행하기
- 이 스킬을 자동 차단 Hook처럼 상시 강제 실행하기
