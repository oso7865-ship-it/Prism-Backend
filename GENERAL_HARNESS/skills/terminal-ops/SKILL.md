# Terminal Ops

> 목적: 터미널 명령 실행 전후의 안전성, 목적, 결과 증거를 기록한다.  
> 사용 위치: `GENERAL_HARNESS` 공통 스킬  
> 출력물: 터미널 실행 기록

---

## 0. Harness Control Rule

- 이 스킬은 `00.HARNESS_RULES.md`의 하위 모듈이다.
- 충돌 시 이 스킬의 절차를 중단하고 `00.QUICK_REF.md`와 `00.HARNESS_RULES.md §3` 우선순위에 따라 상위 규칙을 따른다. 위험 작업 WARN은 사용자 확인 전 스킬 단독으로 진행하지 않는다.

---

## 1. Trigger

- npm/gradle/git 명령 실행
- 검증 스크립트 실행(`scripts/validate-*.mjs` 같은 패키지 내부 validator — 아래 "외부 설치"와는 다르다)
- 삭제/이동/생성 명령 수행
- 신뢰되지 않은 외부 설치 스크립트 또는 환경 변경 명령 검토

---

## 2. Do Not Trigger

- 터미널 실행이 없는 순수 설명
- 명령을 실제로 실행하지 않는 개념 설명
- 사용자가 출력 결과만 해석해달라고 한 경우

---

## 3. Required Inputs

| 입력물 | 필요 이유 |
|---|---|
| 명령 목적 | 왜 실행하는지 확인 |
| 작업 디렉토리 | 실행 위치 확인 |
| 예상 결과 | 성공 기준 확인 |
| 위험도 | 삭제/설치/권한/환경 변경 여부 확인 |

---

## 4. Procedure

1. 명령 목적과 실행 위치를 확인한다.
2. 위험 명령인지 판단한다.
3. 삭제 또는 **신뢰되지 않은 외부** 설치/스크립트 실행이면 **현재 사용자의 실시간 확인이 항상 필요하다(과거 근거로 대체 불가, `04.GATEGUARD.md §6-1`)**. 패키지 내부 `scripts/validate-*.mjs` 실행은 여기 해당하지 않는다. 환경 변경(비파괴적)이면 사용자 확인 또는 유효한 근거로 진행할 수 있다.
4. 명령을 실행한다.
5. stdout/stderr와 종료 상태를 요약한다.
6. 실패 시 원인과 다음 조치를 기록한다.

---

## 5. Quality Gate

| 판정 | 기준 |
|---|---|
| PASS | 명령 목적, 작업 디렉토리, 위험도, 실행 결과, 검증 의미가 명확함 |
| WARN | 실행은 가능하지만 환경 차이, 권한, 의존성, 부작용 가능성이 일부 남아 있음 |
| FAIL | 위험 명령의 근거/확인 없이 삭제·설치·환경 변경을 진행하거나 실행 위치가 불명확함 |

---

## 6. Output Format

```md
## Terminal Ops 결과

- 사용 이유:
- 확인한 입력물:
- 실행한 명령:
- 실행 위치(CWD):
- 종료 코드(exit code):
- stdout/stderr 요약:
- 위험 명령 여부 및 사전 확인 여부:
- 판단 결과:
- PASS/WARN/FAIL:
- 위험 WARN 여부:
- 다음 연결:
```

---

## 7. Handoff

다음 연결: 이 스킬 자신의 §5 판정(PASS/WARN/FAIL)이 명령 실행 자체의 최종 판정이다 — 터미널 실행에는 별도로 대응하는 gates 폴더의 Gate가 없다. 단, 실행 결과가 Gate 대상 산출물(API/DB/문서/스킬 등)에 영향을 줬다면 그 산출물에 대해서만 `skills/quality-gate/SKILL.md`로 넘긴다(터미널 실행 자체를 다시 판정하지 않는다). → `06.REPORT_TEMPLATE.md`

---

## 8. Anti-Patterns

- 작업 디렉토리 확인 없이 명령 실행하기
- 삭제/강제 옵션을 확인 없이 사용하기
- 명령 실패를 무시하고 다음 단계로 가기
- 자동 검증 PASS를 내용 품질 PASS로 보고하기
