# Security Review

> 목적: 인증, 권한, 입력값, 민감정보, 외부 연동, 결제 주변 보안 흐름을 검수한다.  
> 사용 위치: `GENERAL_HARNESS` 공통 스킬  
> 출력물: 보안 검수

---

## 0. Harness Control Rule

- 이 스킬은 `00.HARNESS_RULES.md`의 하위 모듈이다.
- 충돌 시 이 스킬의 절차를 중단하고 `00.QUICK_REF.md`와 `00.HARNESS_RULES.md §3` 우선순위에 따라 상위 규칙을 따른다. 위험 작업 WARN은 사용자 확인 전 스킬 단독으로 진행하지 않는다.

---

## 1. Trigger

- 로그인/JWT/세션/권한/관리자 기능
- 민감정보 저장/로그/전송 검토
- 외부 API 연동
- 결제/환불/웹훅 주변 기능
- 타 사용자 리소스 접근 가능성이 있는 기능

---

## 2. Do Not Trigger

- 정적 UI 문구 수정
- 공개 정보 문서 작성
- 보안 영향이 없는 단순 레이아웃 조정

---

## 3. Required Inputs

| 입력물 | 필요 이유 |
|---|---|
| `07.SECURITY_BASELINE.md` | 전역 보안 최소 기준 확인 |
| `gates/security-gate.md` | 보안 Gate 기준 확인 |
| API/DB/결제 명세 | 보안 영향 범위 확인 |
| 로그/비밀값 정책 | 민감정보 노출 여부 확인 |

---

## 4. Procedure

1. 기능이 민감 기능인지 분류한다.
2. 인증 필요 여부를 확인한다.
3. 사용자/소유자/관리자 권한 기준을 확인한다.
4. 서버 입력값 검증을 확인한다.
5. 토큰, 비밀번호, API Key, 결제키 같은 민감정보 노출 여부를 확인한다.
6. 실패 응답과 로그 기준을 확인한다.
7. 외부 서비스 연동이 있으면 응답의 인증성/무결성 검증, 타임아웃, 실패 시 처리 정책을 확인한다(외부 연동이 없으면 N/A).
8. Security Gate로 PASS/WARN/FAIL을 판정한다.

---

## 5. Quality Gate

| 판정 | 기준 |
|---|---|
| PASS | 인증, 권한, 입력값 검증, 민감정보, 로그, 실패 응답 기준이 모두 확인되고, 외부 연동이 있으면 인증성/무결성/타임아웃/실패 정책도 확인됨 |
| WARN | 직접 취약점은 아니지만 정책 문서화, 로그 마스킹 중 일부가 약하거나, 외부 응답 검증이 일부만 있음(위조/무결성 중 하나라도 다룸) |
| FAIL | 권한 검사 없음, 비밀값 노출, 민감정보 로그 출력, 타 사용자 리소스 접근 가능성이 있음, 또는 외부 연동이 있는데 인증성/무결성 검증과 실패 정책이 전혀 없음(`07.SECURITY_BASELINE.md §5`, `gates/security-gate.md §2`와 동일 기준) |

---

## 6. Output Format

```md
## Security Review 결과

- 사용 이유:
- 확인한 입력물:
- 민감 기능 등급(High/Medium/Low):
- 인증 방식:
- 권한 검증 위치(서버/클라이언트):
- 민감정보 노출 여부(코드/로그):
- 외부 응답 검증 여부(해당 시):
- 판단 결과:
- PASS/WARN/FAIL:
- 위험 WARN 여부:
- 다음 연결:
```

## 8. Anti-Patterns

- 인증만 확인하고 권한 검사를 생략하기
- 클라이언트 검증을 서버 검증으로 착각하기
- 외부 API 응답을 무조건 신뢰하기
- 민감정보를 디버그 로그에 남기기
