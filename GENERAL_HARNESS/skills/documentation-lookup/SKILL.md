# Documentation Lookup

> 목적: 프로젝트 버전과 공식 문서 근거를 대조해 API·설정의 불확실성을 해소한다.
> 출력물: 확인한 버전, 근거, 적용 가능한 결론과 미확인 사항.
> 출처: ECC documentation-lookup을 기술 중립 절차로 재작성했다. 원 고지는 `skills/documentation-lookup/LICENSE`, 고정 출처는 `_SOURCE_MAPPING.md`에 있다.

## 0. Harness Control Rule

- 이 스킬은 `00.HARNESS_RULES.md`의 하위 모듈이다.
- 충돌 시 중단하고 상위 규칙을 따른다. 위험 작업 WARN은 사용자 확인 전 스킬 단독으로 진행하지 않는다.

## 1. Trigger

- 사용 중인 API·설정 키의 존재, 지원 버전, deprecated 동작이 불확실할 때.
- 업그레이드나 외부 연동에서 버전별 호환성을 확인해야 할 때.

## 2. Do Not Trigger

- 일반 개념 설명, 외부 동작과 무관한 문구 수정.
- 동일 버전에 대한 유효한 근거가 이미 있고 해당 근거가 변경되지 않은 경우.

## 3. Required Inputs

- 확인할 질문, 관련 코드·설정 경로, 선언 버전과 확인 가능한 잠금·실행 버전.
- 사용 가능한 공식 문서·공식 저장소·문서 조회 도구.

## 4. Procedure

1. 질문을 API·옵션·호환성처럼 확인 가능한 단위로 한정한다.
2. manifest의 선언 범위, lockfile의 해결 버전, 실행 환경의 버전을 구분한다. 확인하지 못한 버전은 추정하지 않는다.
3. 해당 버전 공식 문서·릴리즈 노트·공식 저장소를 확인한다. 문서 조회 도구는 선택 경로이며 자동 설치하지 않는다. 로컬 공식 자료도 근거가 될 수 있다.
4. 현재 코드와 근거를 대조한다. 최신 문서만 확인했다면 이전 버전 지원 여부는 미확인으로 남긴다. 조회 불가와 검색 결과 없음을 구분한다.
5. 출처 경로/URL, 확인일, 버전, 결론, 남은 불확실성을 호출 단계에 반환한다. 외부 질의에 비밀값·비공개 코드 전체를 보내지 않는다.

## 5. Quality Gate

| 판정 | 기준 |
|---|---|
| PASS | 핵심 결론이 확인한 버전 및 공식 근거와 연결됨 |
| WARN | 일부 버전·문서에 접근하지 못해 결론 범위를 제한함; 진행 위험은 GateGuard로 판단 |
| FAIL | 근거 없이 지원을 확정하거나 중대한 버전 차이를 숨김 |

문서 조사 PASS는 실제 실행·연동 PASS가 아니다.

## 6. Output Format

| 질문 | 선언/해결/실행 버전 | 근거·확인일 | 적용 결론 | 미확인 |
|---|---|---|---|---|
| 확인 대상별 기록 | 확인한 수준만 | 공식 출처 | 적용 범위 | 조회 한계 |

조사 판정과 후속 실행 검증 필요 여부를 별도로 적는다.

## 7. Handoff

호출한 계획·구현·진단 단계로 반환한다. 계획이면 `skills/planning/SKILL.md`, 실제 변경 검증이면 `skills/verification-loop/SKILL.md`, 기록이 필요하면 `06.REPORT_TEMPLATE.md`를 따른다.

## 8. Anti-Patterns

- 프레임워크 이름이 나왔다는 이유만으로 전체 문서를 읽기.
- 최신 문서 확인을 현재 프로젝트 실행 성공으로 보고하기.
- 문서를 찾지 못한 것을 API가 없다는 증거로 사용하기.
