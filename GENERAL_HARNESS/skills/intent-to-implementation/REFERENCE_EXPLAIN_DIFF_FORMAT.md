# Reference: 변경 설명 형식

> `skills/intent-to-implementation/SKILL.md`의 보조 참조 문서다. 단독 스킬이 아니며, 상위 스킬의 Harness Control Rule을 그대로 따른다.

사용자가 문법이 아니라 **실행 흐름을 재구성할 수 있게** 변경을 가르친다. 아래 순서는 도움이 될 때 사용하고, 분량은 변경의 크기에 비례시킨다.

## 1. 배경

변경을 이해하는 데 필요한 기존 시스템만 설명한다:

- 관련 컴포넌트와 각각의 책임
- 이전의 요청·데이터 흐름

초보자에게는 낯선 용어를 처음 등장할 때 정의한다.

## 2. 문제 또는 요구사항

- 어떤 동작이 없었거나 잘못됐는지
- 왜 이전 동작으로는 요구사항을 만족할 수 없었는지
- 어떤 관찰 가능한 결과가 필요했는지

## 3. 핵심 아이디어

파일별 상세보다 **멘탈 모델**을 먼저 준다. 구체적 요청, 예시 데이터, 짧은 시나리오를 사용한다.

> 예: 컨트롤러가 요청을 받고, 서비스가 허용 여부를 결정하고, 리포지토리가 결과를 저장한다.

## 4. 실행 흐름

실제 순서를 따라간다:

1. 트리거 또는 요청
2. 경계에서의 파싱·검증
3. 비즈니스 결정
4. 상태·영속성 변경
5. 응답, 이벤트, UI 갱신

경로를 실질적으로 바꾸는 조건 분기와 조기 종료를 언급한다.

## 5. 코드 변경

파일을 알파벳순으로 나열하지 말고 **책임 단위로 묶는다**. 중요한 변경마다:

- 무엇이 바뀌었는지
- 왜 거기에 있어야 하는지
- 무엇이 이것을 호출하고, 이것이 다음에 무엇을 호출하는지

모든 줄을 해설하지 않는다.

## 6. 검증

어떤 동작을 검증했고 무엇이 미검증으로 남았는지 밝힌다. 검증 기준 자체는 `skills/verification-loop/SKILL.md`가 소유한다.

## 7. 이해도 확인(선택)

교육 가치가 있는 변경에 한해, 중간 난이도 질문 3~5개를 선택적으로 제시한다:

- 계층 책임
- 데이터·요청 흐름
- 핵심 설계 선택의 이유
- 기대되는 실패 동작

사소한 수정이나 간결한 인계만 원하는 경우에는 퀴즈를 붙이지 않는다.

## 설명 깊이

| 수준 | 포함 내용 |
|---|---|
| 간결 | 결과, 핵심 아이디어, 검증 |
| 초보자 | 배경, 용어, 실행 흐름, 책임 단위 코드 묶음, 선택적 퀴즈 |
| 숙련자 | 트레이드오프, 계약, 불변식, 실패 모드 |

대화에서 수준을 추론하되, 사용자가 지정하면 그것을 따른다.
