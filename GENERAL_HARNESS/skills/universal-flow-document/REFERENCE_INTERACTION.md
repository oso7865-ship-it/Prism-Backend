# Reference: 결과 버튼·시나리오·왼쪽 탐색

> 적용: 이 스킬로 인터랙티브 HTML을 생성·갱신할 때 읽는다. JSON의 의미를 바꾸지 않고 사용자가 경로를 고르는 방식을 정한다.

## 1. 기본 화면과 결과 버튼

첫 화면은 `전체`다. 차트 위에 `전체 · 완료 · 실패` 세 버튼을 항상 나란히 표시한다. 모든 시나리오를 한 select에 넣는 방식으로 대체하지 않는다. 버튼은 결과 분류, 하위 선택은 해당 결과에 도달하는 구체적인 경로다.

| 버튼 | 데이터 기준 | 표시 조건 |
|---|---|---|
| 전체 | 선택 시나리오 없음 | 항상 표시, 최초 선택 |
| 완료 | scenario.kind = success | 항상 표시 |
| 실패 | scenario.kind = failure | 항상 표시 |
| 보류 | scenario.kind = hold | 해당 시나리오가 있을 때 추가 |
| 진행 중 | scenario.kind = ongoing | 해당 시나리오가 있을 때 추가 |

- 완료·실패에 시나리오가 0개면 `완료 0`처럼 개수와 비활성 상태를 표시하고 ‘등록된 완료 경로 없음’을 설명한다. 실제 업무에 성공/실패가 없다고 단정하지 않는다.
- 추가 버튼은 데이터에 의미가 있는 결과만 표시한다. 검증 Gate의 PASS/WARN/FAIL, 구현 상태, HTTP 메서드를 결과 버튼과 섞지 않는다.
- 임의의 새 kind를 JSON에 넣지 않는다. 기존 kind로 설명할 수 없는 실제 결과가 있으면 근거와 스키마·검증기 지원을 먼저 확인한다.
- 표시 개수는 시나리오 수다. 같은 종료점에 도달해도 경로가 다르면 각각 센다. failureCases 개수나 실패 노드 수를 대신 쓰지 않는다.

## 2. 선택 동작

| 선택 상태 | 하위 선택 UI | 차트·설명 |
|---|---|---|
| 전체 | 숨김 | 모든 분기·단계 표시, 특정 경로 강조 해제 |
| 해당 결과 1개 | select 생략, 경로명 표시 | 그 경로를 즉시 선택 |
| 해당 결과 2개 이상 | `완료 경로` 또는 `실패 원인` 등 라벨이 있는 select | 이전 선택 복원, 없으면 데이터 순서의 첫 경로 선택 |
| 해당 결과 0개 | 없음, 버튼 비활성 | 현재 선택 유지 |

- 보류·진행 중도 동일한 0/1/여러 개 규칙을 쓴다. 버튼 아래에는 선택된 경로명·요약을 보여 자동 선택을 숨기지 않는다.
- 실패 select에는 해당 kind의 시나리오만 넣는다. `입력 누락 → 요청 거절`, `외부 서비스 응답 없음 → 재시도 중단`처럼 원인과 결과를 구별할 수 있는 제목을 쓴다. 중복 제목에는 원인 단계나 확인된 코드를 보조 표기한다.
- 한 시나리오의 failureCases가 여러 개이면 연결된 사례를 모두 상세 패널에 표시한다. 선택 옵션을 failureCases마다 복제하지 않는다.
- 중간 실패를 복구해 완료한 시나리오는 완료에 속한다. 실패 버튼으로 옮기지 않으며, 복구 단계·실패 설명은 완료 경로 안에 남긴다.
- 강조할 선은 선택 시나리오의 path/edgePath 순서를 따른다. 비선택 단계는 읽을 수 있게 약화하고 ‘이 경로에서 미실행’을 표시한다. 모든 완료 경로를 합쳐 존재하지 않는 한 경로처럼 보여주지 않는다.
- 실패 패널은 발생 단계·조건·영향·다음 행동·재시도 조건을 표시한다. 보류는 필요한 입력·재개 조건, 진행 중은 관측 범위·종료 조건을 표시한다.

## 3. 상태·키보드·주소

- flowId와 scenarioId를 선택 상태의 기준으로 삼고 결과 버튼은 scenario.kind에서 도출한다. 전체는 scenarioId가 없는 상태다. 결과와 시나리오가 서로 어긋나는 별도 상태를 저장하지 않는다.
- 결과별 마지막 선택은 Flow마다 독립적으로 기억한다. 전체를 눌러도 현재 Flow 안의 기억은 유지한다. 다른 Flow로 이동하면 전체로 시작하고 이전 Flow의 시나리오를 적용하지 않는다.
- 직접 주소의 flow/scenario는 유효하면 복원하고 결과 버튼도 함께 선택한다. 삭제되었거나 다른 Flow의 scenario면 전체로 돌아가 이유를 짧게 표시한다. 없는 경로를 자동 생성하지 않는다.
- 기존 `#flow=…&scenario=…` 주소는 유지한다. 브라우저 뒤로/앞으로의 복원은 입력 변경 이력 정책과 함께 검수한다.
- 버튼 묶음은 이름 있는 group과 실제 button, 선택 상태는 aria-pressed로 제공한다. Tab으로 이동하고 Enter/Space로 실행한다. tablist 역할을 쓰면서 방향키 동작을 생략하지 않는다.
- 하위 select에는 보이는 label을 연결한다. 버튼 전환 시 포커스를 강제로 select로 옮기지 않는다. 숨길 select에 포커스가 남는 경우 선택 버튼으로 돌린다.
- 선택 결과 안내는 짧은 polite 상태 영역으로 알린다. 확대 도구는 결과 버튼과 별도 묶음으로 두고 작은 화면에서는 다음 줄로 이동한다.

## 4. 왼쪽 검색·내비게이션

데스크톱 왼쪽은 `목록 제목 → 검색 → 선택적 분류 → 결과 수 → 그룹별 흐름 목록` 순서다. 검색을 목록 토글이나 분류 메뉴 안에 숨기지 않는다. Flow가 하나여도 검색 입력은 표시한다.

- 검색에는 보이는 `흐름 검색` 라벨과 예시 placeholder를 둔다. placeholder만 라벨로 사용하지 않는다. 입력·지우기 조작 영역을 확보한다.
- title·summary·group/category와 존재하는 API method/path를 검색한다. 앞뒤 공백과 영문 대소문자는 무시하고, 여러 검색어는 각 단어가 검색 대상 텍스트에 모두 포함되면 일치한다. 한국어 IME 조합을 방해하지 않는다.
- 검색과 분류는 교집합으로 적용한다. `3 / 전체 12개`처럼 결과 수를 표시한다. 0개면 빈 목록 대신 안내와 검색/필터 초기화 버튼을 제공한다.
- 검색은 탐색 목록만 바꾼다. 입력 중 본문 Flow나 시나리오를 자동 전환하지 않는다. 현재 Flow가 검색에서 빠지면 본문은 유지하고 ‘현재 흐름은 검색 결과 밖에 있음’을 알린다.
- 검색 결과를 선택해도 검색어·분류는 유지한다. 초기화는 명시적 지우기/초기화 조작에서만 한다. Flow 선택은 §3에 따라 전체 보기로 시작한다.
- 현재 항목은 aria-current와 배경·테두리/선택 표식을 함께 쓴다. 그룹 제목은 비조작 텍스트로, 항목 제목과 메서드/경로는 서로 다른 텍스트 계층으로 표시한다.
- 모바일에서는 첫 화면에 `흐름 검색·목록` 버튼을 보이게 둔다. 열면 검색 입력이 목록보다 먼저 나온다. 접히는 패널은 aria-expanded/aria-controls를 연결하고 숨김 상태를 키보드에서도 제외한다.
- 모바일 목록에서 Flow를 선택하면 패널을 닫고 본문 제목으로 포커스를 이동한다. Escape로 닫으면 열기 버튼으로 돌아간다. 모달형으로 구현할 때만 포커스 가두기와 배경 비활성화를 함께 구현한다.
