# Reference: 결과 탐색 UI 검수와 생성기 적용

> 적용: HTML 생성·갱신에서는 실제 브라우저 검수, 스킬 문서만 수정할 때는 규칙의 모순·누락 대조에 사용한다. 문서 검수와 UI 구현 검수의 결과를 구별한다.

## 1. 생성기와 지침의 관계

현재 내장 build 명령은 왼쪽 검색·분류 목록과 결과 버튼(`전체`, `완료`, `실패`, 데이터가 있을 때 `보류`, `진행 중`)을 출력한다. 한 결과에 경로가 여러 개일 때만 하위 select를 표시하고, 0개 버튼은 비활성화하며, 1개 결과는 버튼에서 바로 선택한다.

- 이번 결과 버튼·CSS·검색 기준은 생성 지침이자 공용 생성기의 기본 동작이다. 스킬 지침만 수정하라는 요청에서는 기존 HTML·데이터·생성기·CSS 자산을 재작성하지 않는다.
- 이후 HTML 생성/갱신 요청에서는 `skills/universal-flow-document/REFERENCE_INTERACTION.md`와 `skills/universal-flow-document/REFERENCE_VISUAL.md`를 읽고 현재 생성기와 대조한다. 생성기 출력도 실제 데이터와 브라우저에서 다시 검수해야 한다.
- 요청 범위에 맞게 공용 생성기/뷰어/CSS를 보강하거나 해당 산출물의 재현 가능한 템플릿을 구성한 뒤 아래 검수를 수행한다. 생성 HTML만 수동으로 고쳐 다음 build에서 되돌아가게 하지 않는다.
- FlowDocument의 ID·kind·path·edgePath를 표현 계층에서 활용한다. 화면 버튼을 위해 업무 데이터나 실패 의미를 바꾸지 않는다. 새 필드가 실제로 필요할 때만 형식 계약을 변경한다.
- 공용 생성기를 바꾸면 이 절의 상태 설명과 인수 시나리오를 함께 갱신한다. 브라우저 도구를 쓸 수 없으면 미검증을 표시하고 UI PASS를 주장하지 않는다.

## 2. 인수 시나리오

실제 생성 대상의 모든 시나리오를 대조한다. 공용 뷰어를 바꿀 때는 실제 데이터에 없는 0/1/여러 개 경계도 가상 예제로 보완하되 제품 근거와 구별한다.

| 상황 | 기대 결과 |
|---|---|
| 첫 진입 | 전체·완료·실패가 보이며 전체 선택, 하위 select 숨김 |
| 완료 1개 / 실패 여러 개 | 완료 즉시 강조·select 없음; 실패 선택 시 실패만 고르는 select 표시 |
| 완료 여러 개 / 실패 1개 | 완료 경로 select 표시; 실패 즉시 강조·select 없음 |
| 완료 또는 실패 0개 | 해당 기본 버튼은 개수 0·비활성; 현재 상태 변화 없음 |
| hold/ongoing 있음·없음 | 보류/진행 중 버튼을 실제 데이터가 있을 때만 추가 |
| 복구 후 완료 | 완료에서 선택되며 실패·보상·재시도 구간도 실제 순서대로 강조 |
| 같은 노드 사이 여러 선 | edgePath가 지정한 선만 강조; 미진행 분기와 실패 후 조치 구분 |
| 전체 → 결과 → 세부 경로 → 다른 결과 → 복귀 | 같은 Flow 안의 마지막 세부 선택 복원; 전체는 모든 강조 해제 |
| 다른 Flow/상세 흐름 이동 | 새 Flow 전체로 시작; 이전 Flow의 시나리오 누출 없음 |
| 주소 복원·뒤로/앞으로 | 유효한 flow/scenario와 결과 버튼 일치; 오래된 ID는 전체와 짧은 안내 |
| 키보드 버튼·select·노드 | Tab/Enter/Space 및 native select 조작 가능; 선택 상태와 실제 포커스 일치 |
| 왼쪽 검색 | Flow 1개여도 표시; 한국어·영문·API 경로로 검색; 입력 중 본문 유지 |
| 검색+분류·선택·초기화 | 교집합 결과와 개수 일치; Flow 선택 후 검색 유지; 초기화로 복원 |
| 검색 0건 / 현재 Flow 제외 | 안내·초기화 제공; 현재 본문 유지와 검색 밖 상태 표시 |
| 긴 메뉴/경로/제목/실패 설명 | 검색 머리 영역 유지, 목록만 스크롤, 읽을 수 있는 줄바꿈 |
| 노드가 많은 긴 차트 | 차트가 SVG 전체 높이로 펼쳐짐; 내부 세로 스크롤·max-height 없음; 페이지 스크롤로 마지막 노드까지 연속 탐색 |
| 모바일 검색·목록 | 열기 버튼에 검색 명시, 열면 검색이 먼저 보임; 선택/Escape 닫기와 포커스 복원 |

## 3. 시각 검수 증거

- 390/1280px를 기본으로, 긴 메뉴·추가 버튼·계약이 있으면 320/760px도 확인한다. 브라우저 200% 확대에서도 검색과 주요 조작이 겹치거나 사라지지 않는지 확인한다.
- 캡처는 전체 첫 화면, 실패 세부 선택, 여러 완료의 선택, 왼쪽 검색 결과/0건, 모바일 패널을 포함한다. 해당 상태가 없는 실제 데이터는 적절한 가상 예제로 경계를 검수했다고 밝힌다.
- 페이지 가로 넘침, 패널 검색의 잘림, sticky 헤더 겹침, 버튼 줄바꿈, 차트 내부 세로 스크롤 부재, 필요한 차트 가로 이동, 노드 라벨/화살표 충돌, 키보드 포커스를 확인한다. 가장 긴 실제 흐름에서 차트 컨테이너 높이와 SVG 렌더링 높이가 맞고 마지막 노드가 내부 스크롤 없이 보이는지 측정한다.
- 활성/비활성/선택/hover/focus/disabled별 실제 전경·배경 조합을 확인한다. 색상 토큰을 선언한 사실만으로 대비 검수 완료라 하지 않는다.
- 검색 결과 수, 선택 버튼/시나리오/실제 강조 edge ID를 원본 데이터와 대조한다. 콘솔 오류와 안전한 source URL·HTML 텍스트 처리도 기존 검수 범위에 포함한다.
- 인쇄 요청이 있으면 미리보기까지 별도 확인한다. 화면 검수만으로 인쇄·PDF를 PASS 처리하지 않는다.

## 4. 판정

- PASS: 요청 범위에서 규칙 또는 실제 구현을 검수하고 그 둘을 분명히 구분했으며, 필수 동작·표현 누락이 없다.
- WARN: 브라우저/인쇄 등 필요한 실제 확인을 수행할 수 없고 확인하지 못한 범위를 표시했다.
- FAIL: 단일 전체 시나리오 select를 새 결과 버튼 계약 충족으로 간주, 왼쪽 검색 미노출, 보류를 실패에 혼합, 시나리오/버튼/강조 불일치, 차트를 내부 세로 스크롤에 가둠, 필수 조작 가림·깨짐.

상위 Skill Gate·Document Gate의 의미를 바꾸지 않는다. 문서만 수정한 작업의 PASS는 HTML 구현 PASS가 아니다.
