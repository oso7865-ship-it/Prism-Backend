# Reference: HTML 색상·CSS·레이아웃

> 적용: 이 스킬의 HTML 표현을 만들거나 보강할 때 읽는다. 사용자 제공 기존 차트의 따뜻한 바탕·녹색/붉은색 경로·밀도 있는 왼쪽 탐색을 재사용 가능한 기준으로 옮겼다. 제품 이름과 데이터는 복제하지 않는다.

## 1. 표현 토큰

별도 브랜드 지시가 없을 때 아래 토큰을 기본으로 삼는다. 원본 계열을 유지하되 글자·선·버튼 대비는 실제 조합으로 확인한다. 색 이름을 각 컴포넌트에 하드코딩하지 않는다.

| 역할 | 기본값 | 사용 |
|---|---|---|
| paper / surface / sidebar | #f3f4ef / #fcfcf8 / #f8f9f3 | 페이지 / 카드 / 왼쪽 패널 |
| ink / muted / line | #263e39 / #5b6d65 / #d9dfd5 | 본문 / 보조 글자 / 장식 구분선 |
| green / mint | #246756 / #e1eee5 | 완료·전체 선택 / 선택 항목·완료 배경 |
| red / rose | #a04438 / #f9ebe5 | 실패 선·선택 / 실패 설명 배경 |
| amber / sand | #765a22 / #f2ead8 | 보류·판단 / 보류·판단 배경 |
| blue / ice | #3c607e / #e9f0f6 | 진행 중·외부 연결 / 보조 상태 배경 |
| focus | #865e1d | 키보드 포커스 링; 실제 주변색과 대조 |

- 옅은 line은 장식용이다. 입력·버튼 경계의 식별이 필요하면 더 진한 border 토큰을 둔다.
- 활성 전체/완료 버튼은 green, 실패는 red, 보류는 amber, 진행 중은 blue 바탕과 밝은 글자를 사용한다. 비활성 버튼은 읽을 수 있는 낮은 강조로 남긴다.
- 선택된 노드에는 별도 외곽선/링을 추가한다. 완료·실패의 기존 바탕색을 선택색으로 덮지 않는다.
- 글자는 일반 본문 4.5:1, 큰 글자 3:1, 필요한 조작 경계·포커스는 3:1을 검수 목표로 삼는다. 토큰 표 자체가 대비 통과 증거는 아니다.
- 의미는 색+텍스트+도형/선으로 전달한다. 보류와 판단이 같은 계열이어도 종료 도형·배지로 구분한다.

## 2. 페이지와 왼쪽 패널

- 데스크톱은 2열 grid: 왼쪽 250~290px, 본문 minmax(0, 1fr). 넓은 화면에서도 본문 읽기 폭과 여백을 유지한다. 760px 이하에서는 본문 1열과 접히는 목록을 기본으로 한다.
- 왼쪽 패널은 sidebar 배경·오른쪽 구분선·16~20px 안쪽 여백을 쓴다. 검색과 분류는 패널 상단에 두고 긴 목록만 별도로 스크롤한다.
- 상단 고정 헤더가 있으면 패널 top과 가용 높이는 실제 헤더 높이에 맞춘다. 제목 줄바꿈으로 바뀌는 헤더에 `top:123px` 같은 고정 오프셋을 그대로 복제하지 않는다. 모바일에서는 고정 위치와 높이를 해제한다.
- 패널 내부는 세로 flex, 목록은 min-height:0과 overflow:auto, 머리 영역은 flex-shrink:0을 적용한다. 검색 입력이 목록 스크롤에 밀려 사라지거나 패널 높이에 잘리지 않도록 한다.
- 메뉴 항목은 width:100%, min-width:0, 왼쪽 정렬, 10~12px 패딩, 8~10px 모서리다. 기본은 담백한 배경, hover는 연한 바탕, 현재 선택은 mint와 뚜렷한 선/표식이다. 버튼의 브라우저 기본 스타일에 맡기지 않는다.
- 제목은 본문보다 굵게, method는 짧은 고정 폭 배지, path는 줄바꿈 가능한 작은 코드 글자로 둔다. 긴 URL이 왼쪽 폭이나 본문 위치를 밀지 않도록 한다. 전체 문자열은 접근 가능하게 남긴다.
- 검색 입력·지우기·분류의 높이와 모서리를 통일한다. 검색 아이콘은 보조이며 입력 라벨을 대신하지 않는다. 모바일 열기 버튼에도 ‘검색’을 명시한다.

## 3. 차트 카드와 조작 영역

- 차트는 surface 바탕, 12~15px 모서리, 얇은 테두리와 절제된 그림자로 감싼다. 툴바·범례·차트·상태 안내를 구분선과 간격으로 분리한다.
- 결과 버튼은 연한 바탕 안에 묶은 segmented 형태다. 높이/터치 영역은 최소 44px, 선택은 채워진 색과 글자 굵기로 표현한다. 추가 결과가 생기면 순서를 유지하며 줄바꿈한다.
- 데스크톱은 결과 버튼 → 해당 결과의 세부 선택 → 확대 도구 순서다. 세부 선택이 화면 폭 전체를 독점하지 않도록 최대 폭을 둔다. 확대는 독립된 묶음으로 유지한다.
- 모바일은 결과 버튼, 세부 선택, 확대 도구를 필요한 만큼 행으로 나눈다. 버튼의 글자를 생략하거나 가로로 화면 밖에 밀어내지 않는다. ‘전체’에서는 빈 select 공간을 남기지 않는다.
- 현재 배율 숫자와 `100%` 복원 버튼은 시각적 역할을 구분한다. +/−에는 접근 가능한 이름을, 맞춤에는 현재 차트 영역 기준의 동작을 제공한다.
- 차트 바탕은 옅은 점 격자를 선택적으로 쓸 수 있다. 선과 글자 대비를 방해하면 생략한다.
- 차트 컨테이너는 SVG의 전체 렌더링 높이만큼 늘어난다. max-height, 고정 높이, overflow-y:auto/scroll로 차트를 내부 세로 스크롤 영역에 가두지 않는다. 긴 흐름은 페이지 자체의 세로 스크롤로 처음부터 끝까지 이어서 읽는다.
- 가로 스크롤은 좁은 화면에서 노드 가독성을 유지할 때만 차트 영역에 허용한다. 맞춤 배율로 읽을 수 있으면 먼저 맞추고, 확대 때문에 생긴 가로 이동은 차트 영역 안에서 처리해 페이지 전체 가로 넘침을 막는다. 모바일에서도 세로 스크롤바를 다시 만들지 않는다.

## 4. 차트와 설명 카드

- 기본 처리 노드는 연한 중립/민트, 판단은 sand, 완료는 mint, 실패는 rose, 보류는 sand로 표시한다. source·API 계약 등 보조 정보는 차트 제목에 욱여넣지 않는다.
- 주체와 단계 번호는 노드 위 작은 보조 글자, 핵심 동작은 중앙 제목, 종류는 배지로 구분한다. 긴 제목은 의미 단위로 줄바꿈하고 도형 높이와 선 간격을 함께 조절한다.
- 선은 기본/완료 green 계열, 실패 red, 비동기·콜백·보상은 점선과 의미 라벨로 구별한다. 화살촉도 선 색을 따른다. 분기 라벨에는 surface 계열 받침을 두어 교차선과 겹쳐도 읽히게 한다.
- 비선택 노드의 글자까지 일괄 opacity로 흐리게 하지 않는다. 테두리·바탕·선의 강조를 낮추고 읽을 수 있는 글자와 ‘미실행’ 표기를 남긴다.
- 설명 카드는 번호 → 제목 → 주체/상태 → 설명 → 조건·입출력·상태 변화 → 실패/다음 행동 → 펼치는 근거 순서다. 데이터 없는 항목에는 빈 제목·더미 값을 만들지 않는다.
- 넓은 화면에서 짧은 설명은 2열, 긴 계약/실패 설명은 전체 폭 또는 1열로 둔다. 좁은 화면은 1열이다. 선택 테두리는 레이아웃을 흔들지 않도록 공간을 예약하거나 외곽선을 쓴다.
- 실패 설명은 rose와 red 왼쪽 선, 보류는 sand와 amber 선을 쓴다. 본문의 상태 안내와 노드/카드가 같은 결과를 가리키게 한다.
- 근거·계약의 details/summary도 44px 조작 영역을 확보한다. 긴 코드 블록은 줄바꿈 또는 내부 스크롤로 처리하고 페이지 폭을 확장하지 않는다.

## 5. CSS 유지·접근성·검수

- 토큰 → 기본 요소 → 페이지/탐색 → 툴바 → 차트 → 설명 → 반응형 → 인쇄 순서로 책임을 나눈다. 전역 `button`·`select` 규칙의 반복 덮어쓰기 대신 `.flow-nav`, `.scenario-controls` 등 역할별 선택자를 쓴다.
- hover·focus-visible·선택·disabled·빈 결과 상태를 함께 정의한다. sticky와 overflow 조합으로 포커스 링이 잘리지 않는지 확인한다. 숨김 요소가 flex/grid 규칙으로 다시 나타나지 않게 한다.
- 간격은 4/8/12/16/24/32px 계열, 본문은 약 15~16px/1.6 이상으로 시작한다. 보조 글자를 작게 줄이는 방식으로 긴 내용을 억지로 수용하지 않는다.
- 외부 CDN·폰트 다운로드 없이 시스템의 한국어 글꼴 fallback으로 동작해야 한다. reduced motion에서는 장식 전환과 부드러운 스크롤을 줄인다.
- 인쇄는 조작 UI를 제외하되 문서 제목·선택 경로·근거를 남긴다. 전체 보기인지 선택 경로인지 명시하고 실제 미리보기 검수 없이 인쇄 품질 PASS로 보고하지 않는다.
- 검수 표는 `skills/universal-flow-document/REFERENCE_UI_REVIEW.md`를 따른다. 원본 CSS의 구체적인 색상·위계를 참고하되 특정 API 개수·고정 헤더 높이·작은 터치 영역은 복제하지 않는다.
