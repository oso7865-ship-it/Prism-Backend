# 00. HARNESS QUICK REF

> 목적: 일반 작업에서 `00.HARNESS_RULES.md` 전체 대신 먼저 읽는 런타임 요약본이다.  
> 원칙: 이 문서는 새 규칙을 만들지 않고 `00.HARNESS_RULES.md`, `04.GATEGUARD.md`, `08.QUALITY_GATE.md`의 핵심 실행 규칙만 압축한다.

---

## 1. 충돌 우선순위

충돌 우선순위 7단계는 `00.HARNESS_RULES.md §3`이 소유한다. 이 문서는 표를 복제하지 않고 요약만 남긴다: 안전/보안/데이터 손상 방지 규칙이 항상 최우선이고, 그다음이 사용자의 최신 명시 요청이며, 나머지는 `00.HARNESS_RULES.md §3`을 그대로 따른다.

안전/보안/데이터 손상 방지 규칙은 사용자 최신 요청으로도 덮어쓰지 않는다.

---

## 2. 위험 작업 판정 기준

프로젝트 어댑터가 있으면 context를 읽고 현재 작업 route의 기준 문서만 순서대로 읽는다. 없으면 추가 로딩하지 않는다. 계약과 실패 처리: [Project Adapter](PROJECT_ADAPTER.md).

| 카테고리 | 예시 | 기본 처리 |
|---|---|---|
| 파일 손상 | 삭제, 대량 이동, 덮어쓰기, 위험 터미널 명령 | 사용자 확인 전 진행 금지 |
| 구조 작업 | 스킬 추가/삭제, 문서 번호 변경, 폴더 구조 변경, 하네스 연결 구조 변경 | 사용자 확인 또는 추가 근거 확보 전 진행 금지 |
| DB/데이터 | 스키마 변경, 마이그레이션, 대량 데이터 수정 | 사용자 확인 또는 추가 근거 확보 전 진행 금지 |
| 결제/정산 | 결제 승인, 환불, 웹훅, 금액 검증 | 위험 WARN이면 중단 |
| 인증/권한/보안 | 로그인, 토큰, 관리자 권한, 민감정보 | 위험 WARN이면 중단 |
| 외부 실행 | 외부 설치 스크립트, 공급망 영향 | 사용자 확인 전 진행 금지(예외 없음, 과거 근거로 대체 불가) |
| 환경 변경(비파괴적) | 로컬 환경변수, 설정 파일 값 수정(삭제·외부 설치 제외) | 사용자 확인 또는 추가 근거 확보 전 진행 금지 |

구조 작업 또는 위험 작업에서 애매한 WARN은 일반 WARN처럼 기록 후 진행하지 않는다.

> 관계: `00.QUICK_REF.md §2`는 실행 차단 기준(무엇을 멈추는가)이고, `00.HARNESS_RULES.md §7`은 행동 금지 기준(무엇을 하지 않는가)이다. 두 기준은 보완 관계다.

---

## 3. PASS/WARN/FAIL

의미와 WARN 분기 기준은 `08.QUALITY_GATE.md §2`가 소유하며, 이 문서는 표를 복제하지 않는다. 요약만 남기면: PASS는 다음 단계 진행 가능, WARN은 일반/구조/위험 중 어디에 해당하는지 재판정 필요, FAIL은 원인을 수정하고 재검증 PASS를 받아야 해제된다. **사용자 확인만으로 FAIL을 통과시키지 않는다** — 사용자 확인은 위험 WARN의 진행 여부를 결정할 때 쓰는 절차다.

세부 PASS/WARN/FAIL 의미와 WARN 분기 기준의 소유 문서는 `08.QUALITY_GATE.md`다. 이 문서는 현재 작업에서 필요한 실행 요약만 둔다.

WARN 처리 기준은 `08.QUALITY_GATE.md §3`, `04.GATEGUARD.md`를 따른다. 구조 WARN과 위험 WARN은 사용자 확인 또는 추가 근거 확보 전까지 일반 WARN처럼 처리하지 않는다.
